# 어디가개 이력서용 프로젝트 문구 초안

## 프로젝트명

- 어디가개

## 문제 정의

- 반려견 산책은 현재 위치, 동반 가능 장소, 음수대나 쓰레기통 같은 생활 편의 정보, 반려견 특성에 맞는 이동 거리까지 함께 고려해야 한다.
- 일반 지도 앱만으로는 반려견 산책에 필요한 정보를 한 흐름 안에서 보기 어렵다.
- 어디가개는 산책 장소 탐색부터 추천 경로 선택, 산책 진행, 기록 확인, 반려견 프로필 관리까지 한 서비스 안에서 연결하는 것을 목표로 한 모바일 중심 웹 서비스다.

## 한 줄 소개

- 반려견 정보와 위치 기반 데이터를 결합해 산책 장소 탐색, 추천 경로 선택, 산책 기록 관리까지 이어지는 모바일 지도 UX를 구현한 팀 프로젝트.

## 짧은 프로젝트 소개

### 버전 A

- 반려견 산책에 필요한 탐색과 이동 흐름을 한 화면에서 풀어낸 모바일 웹 프로젝트입니다. Naver Map 기반 지도 위에 반려동물 동반 가능 장소, 음수대, 쓰레기통 정보를 겹쳐 보여주고, 반려견 정보와 현재 위치를 바탕으로 산책 경로를 추천하는 UX를 구현했습니다.

### 버전 B

- 어디가개는 반려견 산책을 위한 지도 서비스입니다. 사용자는 지도에서 주변 장소를 탐색하고, 반려견 정보에 맞는 추천 경로를 선택해 산책을 시작할 수 있으며, 산책 기록과 반려견 프로필, 고객지원 기능까지 하나의 흐름으로 이용할 수 있습니다.

## 내 역할

- 팀 프로젝트에서 프론트엔드 핵심 흐름을 주도했다.
- 지도 탐색 화면과 추천 경로 UX를 중심으로 상태관리, 외부 API 연동, 예외 처리, 기록 화면 연결까지 프론트엔드 구현을 담당했다.
- 팀 전체 성과를 일반화하기보다, 아래 항목은 내가 주도적으로 설계하거나 직접 구현한 프론트엔드 기여를 기준으로 정리했다.

## 핵심 기능

- 지도 기반 산책 탐색: 검색 결과, 반려동물 동반 가능 장소, 음수대, 쓰레기통 정보를 지도와 바텀시트에 함께 노출
- 반려견 정보 기반 추천 경로: 반려견 나이, 크기, 산책 시간/거리 입력값을 바탕으로 추천 경로 조회
- 실시간 산책 진행 상태: 시작 지점 선택, 경로 표시, 산책 중 안내와 상태 전환 처리
- 산책 기록: 오늘 기록, 누적 거리와 시간, 연속 산책 일수, 과거 산책 히스토리 요약
- 반려견 프로필 관리: 프로필 등록/수정, 사진 크롭 후 업로드, 삭제 실패 시 재시도 큐 처리
- 고객지원: 피드백 제출, 공지, 잘못된 정보 제보를 위한 지원 메뉴 구성

## 기술 선택

- 프론트엔드: Next.js 16 App Router, React 19, TypeScript
- 상태관리: Zustand
- 데이터 요청: fetch 기반 서비스 계층, SWR
- 지도/위치: Naver Maps, TMAP 도보 경로 및 역지오코딩 API
- 이미지 처리: Cloudflare Images Direct Upload
- 품질 관리: Node 기반 단위 테스트와 스모크 테스트

## 핵심 기여 bullet

- Naver Map, 바텀시트, 검색 오버레이, POI 포커스 상태를 함께 다루는 지도 화면을 설계하고 구현해 탐색 화면과 경로 선택 화면이 끊기지 않는 모바일 UX를 만들었습니다.
- 반려견 정보 기반 추천 경로 흐름을 구현하면서 외부 추천 API와 TMAP 도보 경로 응답을 프론트엔드에서 사용할 수 있는 형태로 정리해 추천, 선택, 산책 시작까지 이어지는 사용자 흐름을 완성했습니다.
- 시설 정보와 피드백 제출 같은 외부 연동 구간에 Next.js API 프록시와 요청 검증, 응답 정규화를 적용해 프론트엔드가 불안정한 업스트림 형식에 직접 의존하지 않도록 분리했습니다.
- 산책 기록 계산, 경로 추적 정책, 경로 파싱, 시설 데이터 정규화 로직에 테스트를 붙여 지도 기반 서비스에서 발생하기 쉬운 예외와 회귀를 줄일 수 있는 구조를 만들었습니다.

## 문제 해결 사례 한 줄 버전

- 검색 결과, 포커스된 POI, 바텀시트, 추천 경로 상태가 얽힌 지도 화면의 복잡도를 Zustand 기반 상태 분리로 정리해 산책 탐색 흐름을 안정화했습니다.
- 외부 추천 경로 API 응답 형식이 흔들려도 UI가 직접 깨지지 않도록 Next.js Route Handler에서 요청 검증과 응답 정규화를 수행하는 중간 계층을 만들었습니다.
- 산책 중 이탈 경로 재탐색과 경로 redraw 조건이 민감한 문제를 추적 정책 함수와 테스트로 분리해 불필요한 재렌더링과 잘못된 안내 가능성을 줄였습니다.
- 프로필 사진 교체 과정에서 삭제 요청 실패가 생겨도 사용자 데이터가 꼬이지 않도록 재시도 큐를 두어 업로드 이후 정리 작업을 복구 가능하게 만들었습니다.
- 반려동물 동반 장소, 음수대, 쓰레기통처럼 형식이 다른 데이터를 하나의 목록으로 합치는 과정에서 좌표 오류와 중복 id 문제를 정규화 로직과 테스트로 막았습니다.

## 최종 사례 정리

- 상태 설계: 지도 화면 상태 분리, event bus 분리, 검색 맥락 유지
- 외부 연동 안정화: 추천 경로 API 정규화, 시설 데이터 정규화, 위치 권한 에러 처리
- 실시간 지도 UX: 경로 이탈/redraw 정책, 바텀시트 최적화, 시작 지점/역지오코딩/보행 안내
- 사용자 데이터 안정성: 프로필 사진 삭제 재시도 큐, 산책 기록 계산과 streak 처리
- 초기 진입 경험: 온보딩/코치마크 쿠키 레이스 방지

## 가장 강한 사례

### 이력서에 우선 넣을 4개

- 추천 경로 API 정규화: 외부 응답 형식과 에러 메시지가 흔들리는 문제를 Route Handler 기반 프록시 계층으로 흡수해 UI 안정성을 높인 사례
- 경로 이탈/redraw 정책 테스트: 실시간 위치 기반 UX에서 발생하는 흔들림을 추적 정책 함수와 테스트로 통제한 사례
- 지도 상태 전파 구조 재정리: store와 event bus, 훅 분리를 통해 복잡한 지도 상호작용을 확장 가능한 구조로 바꾼 사례
- 바텀시트 성능/레이아웃 안정화: 모바일 지도 화면의 핵심 인터랙션을 height, transform, nav 가림 이슈까지 포함해 다듬은 사례

### 그다음 후보 3개

- 프로필 사진 삭제 재시도 큐: 업로드 성공 이후 정리 실패까지 복구 흐름으로 챙긴 사례
- 시설 데이터 정규화: 서로 다른 위치 데이터 소스를 하나의 탐색 경험으로 통합한 사례
- 검색 맥락 유지: debounce, 최근 검색어, 상태 복원으로 탐색 흐름을 끊기지 않게 만든 사례

### 최종 추천

- 이력서 본문에는 위 `우선 넣을 4개` 중 3개만 고르는 편이 가장 강하다.
- 기본 조합은 `추천 경로 API 정규화 + 경로 이탈/redraw 정책 테스트 + 지도 상태 전파 구조 재정리`를 추천한다.
- UI 완성도를 더 밀고 싶으면 세 번째 대신 `바텀시트 성능/레이아웃 안정화`를 넣는 조합도 좋다.

## 문제 해결 사례 상세 메모

### 1. 지도 화면 상태가 한 번에 너무 많이 바뀌는 문제

- 문제: 지도 화면에서는 검색 결과, 포커스된 POI, 바텀시트 상태, 추천 경로 진입, 산책 시작 흐름이 동시에 바뀌기 때문에 화면 전이가 쉽게 꼬일 수 있었다.
- 해결: 지도 핵심 상태를 스토어와 화면 모드 단위로 분리하고, 추천 경로 선택과 포커스 복귀 흐름을 명시적으로 관리해 상태 전이를 예측 가능하게 만들었다.
- 의미: 단일 화면 안에서 탐색과 경로 선택이 자연스럽게 이어지는 모바일 UX를 만들 수 있었다.

### 2. 추천 경로 API 응답이 프론트에 직접 노출되는 문제

- 문제: 외부 추천 경로 API는 응답 형식이나 에러 메시지가 흔들릴 수 있어, 프론트엔드가 그대로 의존하면 화면이 쉽게 불안정해질 수 있었다.
- 해결: Next.js Route Handler에서 요청 본문 검증, 업스트림 응답 파싱, 비정상 JSON 처리, 추천 경로 형태 정규화를 수행하는 프록시 계층을 만들었다.
- 의미: UI는 안정된 내부 응답 형식만 바라보도록 바뀌었고, 업스트림 변경이나 예외 상황에 대응하기 쉬워졌다.

### 3. 산책 중 경로 이탈과 redraw 정책이 과민하게 동작하는 문제

- 문제: 사용자의 위치가 조금만 흔들려도 오프루트 판정이나 redraw가 과하게 동작하면 산책 경험이 불안정해질 수 있었다.
- 해결: nearest snap 탐색, reroute prompt cooldown, 안정 구간 redraw skip, connector path 생성 조건을 순수 함수로 분리하고 단위 테스트로 검증했다.
- 의미: 지도 기반 실시간 UX에서 자주 발생하는 예외를 코드 레벨에서 통제할 수 있게 됐다.

### 4. 프로필 사진 교체 후 삭제 실패가 누적되는 문제

- 문제: 새 사진 업로드는 성공했는데 이전 사진 삭제 요청이 실패하면 이미지 정리 상태가 꼬일 수 있었다.
- 해결: 삭제 실패 시 localStorage 기반 재시도 큐에 쌓고, 마이페이지 진입 시 남은 삭제 작업을 다시 비우는 복구 흐름을 추가했다.
- 의미: 단순 업로드 성공 여부를 넘어서, 실패 이후의 사용자 데이터 정합성까지 챙기는 구조를 만들었다.

### 5. 시설 데이터 소스마다 형식이 달라 목록 품질이 흔들리는 문제

- 문제: 반려동물 동반 장소, 음수대, 쓰레기통 데이터는 좌표 형식과 필드 구성이 달라서 그대로 합치면 잘못된 좌표나 중복 id가 UI까지 올라올 수 있었다.
- 해결: 소스별 정규화 함수를 분리하고, 잘못된 좌표 필터링, 거리 계산, 정렬, 고유 id 보장을 공통 로직으로 묶었다.
- 의미: 여러 출처의 위치 데이터를 하나의 탐색 경험으로 보여줘도 품질이 크게 흔들리지 않도록 만들었다.

## 오래된 로그에서 뽑은 추가 사례 후보

### 6. 지도 화면의 상태 전파가 복잡해 store 결합도가 높아지는 문제

- 문제: 지도 화면 기능이 늘어나면서 위치 갱신, 경로 상태, UI 전환 이벤트가 하나의 store에 과하게 얽히면 유지보수가 어려워질 수 있었다.
- 해결: 초기 히스토리에서 buffered pub/sub 이벤트 버스와 route state 재정리, map hook 분리를 통해 상태 변경과 UI 반응을 직접 결합하지 않는 구조로 옮겼다.
- 의미: 이후 추천 경로, POI 포커스, 산책 모드 같은 기능이 추가돼도 화면 로직을 확장하기 쉬운 기반이 됐다.

### 7. 바텀시트가 지도 UX를 가리거나 성능을 떨어뜨리는 문제

- 문제: 지도 서비스에서 바텀시트는 핵심 인터랙션이지만, 높이 계산과 transform 처리, bottom nav 가림 여부가 흔들리면 사용성이 급격히 나빠진다.
- 해결: 바텀시트 최적화, transform 조정, height 보정, cover-bottom-nav 조건 분리, fling/open-close 동작 튜닝을 여러 커밋에 걸쳐 다듬었다.
- 의미: 지도, 바텀시트, 하단 네비게이션이 함께 있는 모바일 레이아웃에서 조작감과 시각적 안정성을 확보할 수 있었다.

### 8. 위치 권한 실패가 단순 에러로 끝나는 문제

- 문제: 위치 기반 서비스에서 권한 거부, 위치 확인 실패, 타임아웃이 발생하면 사용자는 왜 동작하지 않는지 이해하기 어렵다.
- 해결: geolocation 에러를 코드별로 분류해 제목, 설명, 다음 행동 제안을 분리한 전역 에러 처리 흐름을 만들고, 모달 시스템과 연결해 사용자 메시지를 구체화했다.
- 의미: 위치 기능 실패를 단순 기술 오류가 아니라 복구 가능한 UX 문제로 다루는 방식으로 품질을 끌어올렸다.

### 9. 초기 진입 시 온보딩/코치마크 상태가 확정되기 전에 메인 화면이 먼저 뜨는 문제

- 문제: 쿠키 기반 온보딩 상태가 확정되기 전에 메인 화면이 먼저 그려지면 깜빡임이나 잘못된 진입 흐름이 생길 수 있었다.
- 해결: 메인 페이지 진입을 쿠키 확인 이후로 미루고, 온보딩 일러스트는 선로딩해 전환 중 빈 화면이나 튀는 느낌을 줄였다.
- 의미: 기능 자체보다 첫 진입 경험의 완성도를 챙긴 사례로 설명할 수 있다.

### 10. 검색 화면을 오갈 때 입력 상태와 결과 맥락이 쉽게 끊기는 문제

- 문제: 지도 검색은 입력값, 정렬, 최근 검색어, 검색 중심 좌표가 함께 유지되지 않으면 사용자가 다시 처음부터 탐색해야 한다.
- 해결: debounce 검색, 최근 검색어 저장, 세션 기반 검색 상태 복원, 하이라이트 표시, 검색 결과를 메인 지도 흐름에 통합하는 구조를 단계적으로 만들었다.
- 의미: 단순 검색 기능 추가가 아니라, 탐색 맥락이 이어지는 검색 UX로 발전시킨 사례로 설명할 수 있다.

## 기술적으로 강조할 포인트

- 지도 화면이 단일 컴포넌트가 아니라 검색, 포커스된 POI, 추천 경로, 산책 상태, 바텀시트 뷰 모드가 얽힌 복합 상태 문제였고, 이를 Zustand 스토어와 서비스 계층으로 나눠 관리했다.
- 외부 API는 바로 UI에 연결하지 않고 Next.js Route Handler를 중간 계층으로 두어 요청 검증, 에러 메시지 정리, 응답 형식 보정, 업스트림 교체 가능성을 확보했다.
- 프로필 사진 업로드는 Direct Upload만 붙인 것이 아니라 크롭, 업로드 URL 발급, 업로드 후 프로필 반영, 삭제 실패 시 재시도 큐까지 사용자 관점의 실패 흐름을 포함해 처리했다.

## 면접용 설명 포인트

### 1. 왜 이 프로젝트가 단순 지도 앱이 아니었는가

- 단순히 핀을 찍는 수준이 아니라, 검색 결과와 생활 편의 정보, 반려동물 동반 가능 장소, 추천 경로, 산책 진행 상태를 한 흐름으로 엮어야 했다.
- 그래서 지도 렌더링보다 상태 전이와 UX 연결이 더 중요한 문제였고, 화면 상태를 명시적으로 분리하는 데 집중했다.

### 2. 어떤 프론트엔드 문제를 해결했는가

- 지도 기반 서비스는 외부 API 응답 형식과 사용자 위치 상태가 자주 흔들린다.
- 추천 경로, 시설 정보, 피드백 제출, 이미지 업로드를 각각 서비스 계층과 API 프록시로 분리해 에러 처리와 응답 정규화를 공통화했다.

### 3. 품질을 어떻게 확보했는가

- 경로 추적 정책, 보행 경로 파싱, 산책 기록 계산, 시설 정규화 같은 순수 로직은 테스트로 검증했다.
- 실사용 화면에서는 업스트림 오류, 잘못된 응답 형식, 업로드 실패 같은 상황을 사용자 메시지와 재시도 흐름까지 포함해 다뤘다.

- "전체 서비스 설계" 같은 넓은 표현보다 "지도·경로 UX와 프론트엔드 연동 주도"처럼 책임 범위를 좁혀 쓴다.
